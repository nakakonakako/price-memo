# 仕様: 使い方タブ

最終更新: 2026-10-08

関連: [project-overview.md](./project-overview.md)

## 1. 役割

アプリの概要と各機能の説明を **機能画面とは分離** して載せるタブ。

- ナビラベル: **使い方**（`TabId: howto`）
- 操作ヒントやレイアウトの補足は **ここに書き、機能画面には書かない**
- PC / スマホで入口や操作が本当に異なる箇所だけ CSS（`lg:` 等）で出し分け。`useMediaQuery` で同文を二重に書かない

## 2. ページ構成（情報設計の順序）

`HowToPage.tsx` は次の順で説明する。詳細文はコンポーネント側が正本とし、本 spec には設計順序のみ記す。

1. **単価メモ概要** … 短い目的説明
2. **基本の流れ（3 ステップ）** … 番号付き。PC は 3 列、スマホは縦並び
3. **買い物メモ** … 役割を先に明示。主フロー約 4 ステップ＋控えめな便利ヒント（店名絞り込み・フォルダへ・メモから外す）
4. **フォルダ** … 品目名 / 店名の比較表と主な操作
5. **値段推移** … 目的、グラフ・記録詳細・店舗絞り込み、端末別入口（PC: フォルダ内グラフ / スマホ: 値段推移タブ）
6. **記録の入力** … 項目表。自由単位は短い補足のみ
7. **PC とスマホの操作** … 端末差を一箇所に集約（レスポンシブな 2 列カード）
8. **単価の考え方** … `unitPrice` / `perHundredPrice` / `formatYen` と一致する計算例

### 主説明から外す（初見に不要・内部寄り）

- 短い日付表記の詳細
- 単価を表示しない画面の説明
- 検索中に新規追加カードが出ない挙動
- 「操作説明をここへ集約している」旨
- 単位自由入力の blur / focus 確定の実装詳細

## 3. 実装パス

`frontend/src/features/guide/components/HowToPage.tsx`

小規模なローカルコンポーネント（ステップ・表・操作カード）を同ファイル内に置いてよい。汎用ガイドライブラリ化はしない。
