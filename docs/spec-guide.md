# 仕様: 使い方タブ

最終更新: 2026-10-08

関連: [project-overview.md](./project-overview.md)

## 1. 役割

アプリの概要と各機能の説明を **機能画面とは分離** して載せるタブ。

- ナビラベル: **使い方**（`TabId: howto`）
- 操作ヒントやレイアウトの補足は **ここに書き、機能画面には書かない**
- PC / スマホで入口や操作が本当に異なる箇所だけ CSS（`lg:` 等）で出し分け。`useMediaQuery` で同文を二重に書かない

## 2. 情報設計の方針

- **320px でも短時間で読める**ことを最優先。通常表示は 1 内容 1 文・短文中心
- 長い説明は削除・短縮し、必要なら `<details>` へ
- 括弧や中黒で情報を連結しすぎない
- 同じ機能説明を複数箇所に繰り返さない
- 見れば分かるタップ・入力・保存の説明は省く
- **見つけにくい機能**（検索からの新規追加、読み仮名、店名絞り込み集計、「フォルダへ」等）は末尾の折りたたみで案内

## 3. ページ構成（設計順序）

`HowToPage.tsx` は次の順で説明する。文言の正本はコンポーネント側。

1. **ヒーロー** … 中央寄せ・stone 系背景。「商品単価を 記録 → 比較 できるアプリです」。旧「単価メモとは」見出し＋長文は廃止
2. **目次** … スマホは `<details>` でコンパクトに開閉。PC は `max-w-3xl` 内の横並びリンク。各セクション見出しに `id` と `scroll-margin` 付きアンカー
3. **基本の流れ** … 共通 `GuideStep` / `GuideSteps` の縦並び 3 ステップ（`lg:grid-cols-3` は使わない）
4. **買い物メモ** … 主表示は最小限の 3 ステップ。平均・最安・直近、店名絞り込み、「フォルダへ」、メモから外しても記録維持は「便利な使い方」`<details>` へ
5. **フォルダ** … 品目名＝商品ごと・店名＝店舗ごとの短い比較 UI と主操作のみ。色・直近件数・並び順などの詳細は載せない
6. **値段推移** … 端末別入口を通常表示（PC: フォルダ内グラフボタン / スマホ: 値段推移タブ）。店舗選択・解除は共通 `GuideStep`
7. **記録の入力** … モバイルは縦カード、広幅は簡潔な表。320px で横スクロール表は禁止。単位「その他…」は `<details>`
8. **PC とスマホ** … 削除・並べ替え・値段推移入口の差分を 1 つの比較 UI に集約
9. **見つけにくい機能** … 末尾 `<details>`。実装で確認した機能のみ（検索からの追加、横断検索、読み仮名、自由単位、「フォルダへ」等）

全主要セクション見出しは同じ stone 背景・rounded・padding のローカル `GuideHeading` を使う。手順 UI は `GuideStep` / `GuideSteps` に統一し、`list-decimal` や別スタイルの行番号は使わない。

**載せない:** 単価の考え方セクション、計算例、`unitPrice` 等の import。

## 4. 実装パス

`frontend/src/features/guide/components/HowToPage.tsx`

小規模なローカルコンポーネント（見出し・ステップ・比較表・目次）を同ファイル内に置いてよい。汎用ガイドライブラリ化はしない。
