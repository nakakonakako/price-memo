# 仕様: 使い方タブ

最終更新: 2026-10-08

関連: [project-overview.md](./project-overview.md)

## 1. 役割

アプリの概要と各機能の説明を **機能画面とは分離** して載せるタブ。

- ナビラベル: **使い方**（`TabId: howto`）
- 操作ヒントやレイアウトの補足は **ここに書き、機能画面には書かない**
- PC / スマホで入口や操作が本当に異なる箇所だけ CSS（`lg:` 等）で出し分け。`useMediaQuery` で同文を二重に書かない

## 2. 情報設計の方針

- **320px でも短時間で読める**ことを最優先。通常表示は 1 内容 1 文・短文中心
- 長い説明は削除・短縮し、必要なら実 UI の静的モックで置き換える
- 括弧や中黒で情報を連結しすぎない
- 同じ機能説明を複数箇所に繰り返さない
- 見れば分かるタップ・入力・保存の説明は省く
- 端末差や見つけにくい機能は **該当する 4 節の中** に分散して載せる。独立セクションは作らない

## 3. ページ構成（設計順序）

`HowToPage.tsx` は **4 節のみ**。文言の正本はコンポーネント側。

セクション定義は `GUIDE_SECTIONS` 配列で一元管理する（`id` / `title` / `englishTitle`）。目次の番号 01〜04、セクション見出し、PC 左ナビのラベルはすべてこの配列から生成する。

1. **01 基本の流れ** … ヒーローなしでページ冒頭から開始。共通 `GuideStep` / `GuideSteps` の縦並び 3 ステップ（`lg:grid-cols-3` は使わない）。各ステップは短い 1 文
2. **02 買い物メモ** … 平均・最安・直近の `StatCell` 風モックを目立たせる。店名絞り込み、「フォルダへ」、PC ドラッグ並べ替え・ゴミ箱ドラッグ、スマホ左スワイプをこの節に集約
3. **03 フォルダ** … 品目名＝商品ごと・店名＝店舗ごとの短文。比較表は載せない。横断検索（`SearchIcon` ボタン）、記録追加 ＋、件数ボタン、複製・編集アイコン、読み仮名、削除操作（スワイプ / ドラッグ中ゴミ箱）を実 UI に合わせた静的モック＋短文で示す
4. **04 値段推移** … PC（`ChartIcon` ボタン）とスマホ（値段推移タブのフォルダ選択）を常に並べた小カードで示す。グラフ操作は共通 `GuideStep`（記録を見る / 店舗で絞る / 全体へ戻す）

**目次**

- **スマホ**: 本文上部の `<details>` でコンパクト表示。横 overflow なし
- **PC（`lg:` 以上）**: 本文左に sticky 縦タイムライン。項目間は dashed / dotted の縦線。リンク名に細い下線。`IntersectionObserver` で active を更新し、active だけ濃い番号・文字・太め下線。クリックで該当節へスクロール
- `MainLayout` の `max-w-3xl` は HowToPage だけ breakout 可。本文は中央付近・約 600–680px 幅。左 nav と本文は 1024px 幅でも重ならない

全節見出しはローカル `SectionHeading` で統一（番号・日本語・薄い英語装飾、`bg-stone-100` 程度の面）。手順 UI は `GuideStep` / `GuideSteps` に統一。

**廃止した独立セクション:** 単価メモとは、記録の入力、PC とスマホ、見つけにくい機能、単価の考え方、ヒーロー、フォルダ比較表、「便利な使い方」折りたたみ。

**載せない:** 単価の考え方、計算例、`unitPrice` 等の import、メモから外しても記録維持の説明、直近記録を開く／すべての記録を見るの説明。

## 4. 実装パス

`frontend/src/features/guide/components/HowToPage.tsx`

小規模なローカルコンポーネント（見出し・ステップ・目次・モック UI）を同ファイル内に置いてよい。汎用ガイドライブラリ化はしない。
