# 仕様: 使い方タブ

最終更新: 2026-10-08

関連: [project-overview.md](./project-overview.md)

## 1. 役割

アプリの概要と各機能の説明を **機能画面とは分離** して載せるタブ。

- ナビラベル: **使い方**（`TabId: howto`）
- 操作ヒントやレイアウトの補足は **ここに書き、機能画面には書かない**
- PC / スマホで入口や操作が本当に異なる箇所だけ CSS（`lg:` 等）で出し分け。`useMediaQuery` で同文を二重に書かない

## 2. 情報設計の方針

- **320px でも短時間で読める**ことを最優先。通常表示は 1 内容 1 文・短文中心
- 長い説明は削除・短縮し、必要なら実 UI の静的モックで置き換える
- 括弧や中黒で情報を連結しすぎない
- 同じ機能説明を複数箇所に繰り返さない
- 見れば分かるタップ・入力・保存の説明は省く
- 端末差や見つけにくい機能は **該当する 4 節の中** に分散して載せる。独立セクションは作らない

## 3. ページ構成（設計順序）

`HowToPage.tsx` は **4 節のみ**。文言の正本はコンポーネント側。

セクション定義は `GUIDE_SECTIONS` 配列で一元管理する（`id` / `title` / `englishTitle`）。目次の番号 01〜04、セクション見出し、PC 左ナビのラベルはすべてこの配列から生成する。

1. **01 このアプリでできること** … 3 つの機能タイル（リスト・単価比較・履歴振り返り）。順序を強制する手順ではない
2. **02 買い物メモ** … 開いた `FolderMemoCard` のレイアウト・余白・クラスに合わせた **操作不能な静的モック**（ヘッダー・フォルダへ・平均/最安/直近・店名/日付・確認日/店名/値段/内容量/補足・今の単価と平均/最安/直近との差・統計に残す）。注釈は ①フォルダへ（開いたときだけ）②統計 ③店名絞り込み ④統計に残す の **4 つのみ**。PC ドラッグ並べ替え・ゴミ箱ドロップ、スマホ左スワイプは実カード形状の操作前→操作後図で示す
3. **03 フォルダ** … 品目名＝商品ごと・店名＝店舗ごとの短文。フォルダカード UI を中心に、①横断検索（`SearchIcon`）②件数で詳細 ③＋で記録追加 ④複製 ⑤編集（`CopyIcon` / `PencilIcon`）の 5 注釈。続けて **「読み仮名を使った検索と並べ替え」ブロック**（下記）と、削除操作（PC ドラッグ中ゴミ箱 / スマホ左スワイプ）の操作前→操作後図
4. **04 値段推移** … PC（フォルダ行の `ChartIcon` ボタン）とスマホ（値段推移タブのフォルダ選択）の入口を小カードで示す。続けて **実 `FolderTrendPanel`**（`compact`）を操作可能なサンプルとして載せる（下記）

**レイアウト・ナビ**

- 各節は背景面・境界・余白で **節ごとに視覚的に分離** する（単調な白枠の縦積みを避ける）
- 各節冒頭に共通スタイルの **リードブロック**（`GuideLead`：やや大きめの行間、淡い tint 背景、左アクセント、角丸）
- 見出し ＞ リード ＞ 手順・箇条書き ＞ UI モックの階層を明確に
- **スマホ**: 本文上部の `<details>` でコンパクト目次。横 overflow なし
- **PC（`lg:` 以上）**: 本文左に sticky 縦タイムライン。項目間は dashed / dotted の縦線。リンク名に細い下線。`IntersectionObserver` で active を更新し、active だけ濃い番号・文字・太め下線。クリックで該当節へスクロール
- `MainLayout` の `max-w-3xl` は HowToPage だけ breakout 可。本文は中央付近・約 600–680px 幅。左 nav と本文は 1024px 幅でも重ならない

全節見出しはローカル `SectionHeading` で統一（番号アクセント・日本語主・薄い英語装飾・`bg-stone-100` 程度の面と subtle depth）。手順 UI（`GuideStep`）は本当に順序がある箇所だけ使う。

**注釈システム（`GuideAnnotation.tsx`）**

- 絶対配置の吹き出し（旧 `GuideCallout`）は使わない。対象の **すぐ隣に通常フローで置く直径 18px の番号マーカー**（`GuideMarker`）と、モック下の **通常フローの説明リスト**（`GuideAnnotationList`：モバイル 1 列、`sm` 以上 2 列）で構成する
- マーカーは操作対象・入力欄に重ねない。説明文・図キャプション・ラベルは **12px（`text-xs`）以上**。実 UI を再現するモック内の小さい補助文字（統計ラベル 10px、店名/日付 9px）は実カードと同寸のまま
- 操作前→操作後図（`GuideBeforeAfter`）：モバイルは縦積み（↓）、`sm` 以上は横並び（→）。アニメーションは使わない（`prefers-reduced-motion` 対応不要）

**セクションテーマ（`guideTheme.ts`）**

01 stone / 02 teal / 03 amber / 04 sky。節の面・見出し背景と番号・リード左バー・注釈マーカー・強調色・区切り線を同じ彩度帯（50/200/500〜700）で揃える。モック内の実アプリ色は変更しない。

**値段推移サンプル（`GuideTrendSample.tsx`）**

- `React.lazy` + `Suspense` で遅延読み込みし、Recharts を初期バンドルに含めない
- 固定のローカル `PriceRecord[]`（単位 g のみ・複数日付・3 店舗。パネルの初期単位 `g` と一致させ、dev の StrictMode でも初期単位が正しく表示されるようにしている）を `records` / `recordsLoading={false}` で渡すため、`FolderTrendPanel` は `listRecords` を呼ばない。保存・書き込み・DB アクセスは一切なし。`TrendsPage` / `FolderTrendPanel` は変更しない
- 店舗選択でグラフ絞り込み、「すべて表示」で復帰、単位/表示切替、点の詳細表示は実コンポーネントの挙動

**メモカードの安全方針**

実 `FolderMemoCard` は `createRecord` を呼べるためガイドにはマウントしない。安全に再利用できる表示専用部品がないため、実カードのクラス・配置（`lg` でヘッダー横並び）を写した静的モックを使う（限界：実カード変更時は手動追従が必要）。

**読み仮名ブロック**

`folderName.ts` / `FoldersPage` の実挙動に基づく：末尾の（読み仮名）は保存名に含まれ、一覧表示は読み仮名を除いた名前（例：牛乳）、検索は読み仮名も対象、名前順は読み仮名をソートキーに使う。ブロックは「フォルダ名入力 `牛乳（ぎゅうにゅう）`」→「保存後の表示 → 牛乳」「検索・名前順 → ぎゅうにゅうを利用」の 2 段階を示す（入力は操作不能の静的表示）。

**廃止した独立セクション:** 基本の流れ、単価メモとは、記録の入力、PC とスマホ、見つけにくい機能、単価の考え方、ヒーロー、フォルダ比較表、「便利な使い方」折りたたみ。

**載せない:** 単価の考え方、計算例、`unitPrice` 等の import、メモから外しても記録維持の説明、未登録検索文字の追加説明、直近記録を開く／すべての記録を見るの説明。

## 4. 実装パス

`frontend/src/features/guide/components/HowToPage.tsx`

同ディレクトリ：`GuideAnnotation.tsx`（マーカー・説明リスト・操作前後図）、`guideTheme.ts`（テーマ）、`GuideTrendSample.tsx`（遅延ロードされるグラフサンプル）。小規模なローカルコンポーネント（見出し・リード・目次・モック UI）は `HowToPage.tsx` に置いてよい。汎用ガイドライブラリ化はしない。
